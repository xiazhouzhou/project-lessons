## 0. 一句话结论

**技术不难，调度和优先级崩了。**

8 屏主链（买石→刮皮→收购→开窗→加工→顾客→结算→次日）在终止前 2 小时已经跑通，
42 条自动化断言 62 秒全绿。真正把项目拖死的是四件事：

1. 立项前置条件**没验就信了旧文档**（IAA「阻塞」了 4 天，实际平台第 1 天就开通）；
2. 验证基建的投入**超过了功能开发的投入**（字体守卫 + 双钩子 + 变异测试 + 像素探针）；
3. 调度上**至少 3 张重复单 + 1 张已被现有工具覆盖的单**，占掉两个完整回合；
4. 报时**从承诺反推而不是从实测吞吐外推**，22:00 硬承诺交付，22:23 迟到。

用户视角只有一句：**"多少天了，我还看不到？"**
——这句是真话，不是情绪。第 4 天晚上才给出第一个能玩的入口，就是失败。

## 1. 立项阶段：三条致命偏差

### 1.1 把「复刻」做成了「按记忆还原」

项目定位是复刻同平台现成游戏。但立项期**没有先拿到原作实机画面**，
而是拿二手描述 + 平台截图拼规格。后果贯穿全程：

- 图鉴 4 个封面全是猜的，只能标「暂定可改」；
- 收藏小屋的入口位置原作里根本没观测到，只能「暂定放早市底栏」；
- 刮皮屏底栏留白比例「未证实」，用 `paddingBottom = 110` 蒙；
- 美术做网格时反复问「原作是这样吗」，因为手上没有原分辨率帧。

**教训**：说「复刻」两个字之前，先取到原作**实机运行画面**（不是商店截图、不是第三方评测）。
拿不到就当场改口径为「同题材原创」，不要留一堆「暂定可改」在仓库里假装是复刻。

自检问题：**开工第一天能不能指着屏幕说「这一帧就是原作那一帧」？** 不能就不是复刻。

### 1.2 信了过期文档，白等一个不存在的前置条件

`docs/IAA配置前置清单.md` 写「IAA 不是代码问题，是项目身份问题：缺 app_id / developer_id，阻塞」。
我信了，把广告算作「等平台/等 owner」的外部阻塞，排到最后。

第 4 天实测 `get_ad_config`：

```
app_id: 996706        developer_id: 504767
status_message: "广告变现已生效"     ad.status: 1
ad_spaces: 1054323(type=1), 1054324(type=2)
synced_at: 2026-10-27T07:11:36Z
```

**四天前就开通了。** 那份文档写于立项期，当时开发目录还错绑在《一锤一个亿》，
项目后来迁到独立项目 `d203298f-…`，文档没人更新。

**教训**：
- 「阻塞项」只能用**平台工具当场复验**，不能引用项目内文档的历史结论；
- 任何标着「待 owner 处理 / 等平台」的条目，超过 24 小时必须重新实测一次；
- 外部依赖**第一天就全部实测到底**，不要留到后期，因为后期它会变成一句「反正要等平台」。

### 1.3 平台/项目身份错绑，没有第一时间发现

立项期 `kit/.project/project.json` 指向的是另一个项目《一锤一个亿》（`m_p9zf`），
在这个目录里构建、提交、配广告，产物会落到错误项目。发现得不够早。

**教训**：开工第一步固定动作——`get_ad_config` + 读 `.project/project.json`，
确认 `project_id` 与本项目一致，再写第一行游戏代码。

## 2. 开发执行：优先级倒挂

### 2.1 结构性缺失被当成「可选优化」

终止时的真实状态：

| 项 | 状态 | 性质 |
|---|---|---|
| 8 屏主链 | 通（42 条断言 / 62s） | 核心 |
| 刮皮屏整屏背景垫 | **缺**（`scrape.lua` 根节点只有 `backgroundColor`） | **结构性** |
| 广告 6 点位 | **未接** | 结构性 |
| 云存档 | **未接** | 结构性 |
| 网格线形 3 个灰阶 / 1px 斜率 | 反复调了 3 轮 | 像素级 |

美术和我把大量时间放在网格线的 **+36 vs +30.2 灰阶、FWHM 14 vs 15、暗槽 -11 vs -4** 上，
而同一时间**刮皮屏整屏没有背景垫**——原作是整屏网格垫，我们那屏是一块深棕纯色，
一眼看就是两个游戏。用户那句「差距很大」，怀疑主要就指这里。

**教训**：
- 每轮开工先问「**用户一眼会看出的最大差异是什么**」，先把那个补上，再谈 1px；
- 「可逆 vs 不可逆」是决定**要不要停下来问**的判据，不是决定**先做什么**的判据。
  结构性缺失优先级永远高于细节打磨，哪怕它是可逆的；
- 三屏并排给用户看时，**先用 5 秒直觉判**，再用像素判。像素全对而观感不对，等于没做对。

### 2.2 验证基建投入产出比失真

终止前实际建成的验证设施：

- `tools/selftest.py` 5 suite / 9 步全量入口；
- 字体守卫：`kit-font-guard.sh`（pre-commit）+ `kit-font-push-guard.sh`（pre-push）+ `install_font_hook.py` 双钩子管理；
- `verify_font_at_ref.py`：从 git commit 对象里直接读 ttf + lua，可审计**任意 ref** 的字体覆盖；
- `selftest_font_hook.py` 20 项自测，含「`--no-verify` 绕过 pre-commit 后 push 仍被拦」；
- `verify_scrape_pixels.py`：像素级证明刮擦是真减法；
- `run_headless.py`：42 条断言 / 62s / 8 屏。

这些**确实抓到了真 bug**（见 §4），但加起来的工时超过任何一个玩法模块。
在「4 天要交付可玩版本」的约束下，这是错的配比。

**教训**：
- 验证基建要有**预算上限**，比如不超过总工时的 20%；
- 什么时候值得建「守卫」：**同一个 bug 会复发第二次**时（字体豆腐块就复发了，值得）；
- 什么时候不值得：**一次性取证**（像素证明刮擦是真的）——跑一次贴结论就行，不必做成常驻套件；
- 变异测试（把实现改坏、看断言会不会红）只在关键断言上做，不要套在所有断言上。

### 2.3 「构建成功」当交付（这条守住了，要写下来）

`maker_build_current_directory` 返回 `preview_refresh: ok / 200`，**不等于游戏能跑**。
本项目守住了这条：每次构建后都真加载、真截图、真点按钮。
但也踩过反面：早期 `main.lua:711` 硬编码 `print("[boot] Start() entered · build=P0-2")`，
**构建标签从不更新**，日志无法区分构建版本，一度以为新包没生效。

**教训**：交付前必须有一条「我按用户会走的流程自己走了一遍」的证据，
构建日志、退出码、`refresh 200` 都不算。

## 3. 协作调度：最大的浪费源

### 3.1 重复派单

同一份「闭环无断点清单」工程师交了 **3 次**，我 3 次都当成新单又派了回去，
他 3 次都回「本轮 0 改动、0 提交，同请求重复投递」。
两个完整回合空转，用户看到的是「另外两个 agent 都在闲着」。

**教训**：
- 派单前**先查仓库**：这个交付物是否已经存在、是否有等价物；
- 每张单给一个**唯一编号**（如 `E-07`），回复里必须引用编号，避免把 A 单的交付当成 B 单的重复；
- 协作 Agent 回「重复投递」时，先自证「我这次要的确实不同」，不要让它再猜一遍。

### 3.2 派了已被现有工具覆盖的活

我让工程师新建 `tools/smoke_loop.py` 把 8 屏闭环做成「一条命令 <3 分钟」。
实际上 `run_headless.py` **早就有 42 条 ASSERT 覆盖全 8 屏，实测 62 秒**。
白派一单，后来撤回。

**教训**：派活前**先跑一遍现有工具并量耗时**，别凭印象判断「这个还没有」。

### 3.3 派了自己 5 分钟能做完的活

我派工程师补「成就/排行页签点击回归」，等他一个回合。
后来我自己写了个 lua 探针（三态各点非当前页签），**18 checks GREEN**，
再做变异体（`onClick` 恒送 `"codex"`）→ 同一探针 **RED / 4 failed**。
整个活 5 分钟。

**教训**：**≤15 分钟的活自己做，不要派**。派单的价值是并行，不是省力。
判断标准：这个活如果我自己做要多久？<15 分钟就自己干。

### 3.4 协作 Agent 自报的数字必须复算

- 美术把「当前版 / 候选版」文件名搞反，报「底色青绿」实为橄榄，照他说的改差点把对的换成错的；
- 美术从相关系数 0.799 > 原作 0.628 推断「我的线边缘太锐，要加高斯柔化」——
  **推反了**：相关系数高只说明「更规则」，原作低是因为 JPEG 噪声。逐值打线形出来，
  原作斜率 9.4 灰阶/px，候选 5.7，**原作更陡**，加柔化只会更远；
- 美术按 L709 口径反解 +42.6 得到「抬高 37」，但**灰阶口径实测只有 +30.2**。
  两个口径不是一回事，他没说清，我也没先问清。

**教训**：协作 Agent 报的每一个数字，**换一套口径自己算一遍**。
口径不同的数字放同一张表里，等于没说。

### 3.5 平台超时是硬约束

协作 Agent 没有后台常驻：一个回合被平台超时杀掉（实测约 1 小时）。
我一次给 3 件事，他做到第 2 件被杀，前 2 件的成果也拿不全。

**教训**：单回合只塞 **≤10 分钟能收口**的活。要并行就多派几个回合，别塞一个大包。

## 4. 有效的做法（下一个项目继续用）

这些是 4 天里真正省了时间的部分，别因为项目失败就一起丢掉：

1. **真减法验证**：刮皮屏用离屏 RT + `NVG_DESTINATION_OUT` 真减像素。
   证明方式：41% 覆盖与开窗 55% 后**同一像素 90.8% 逐像素完全一致**——
   若是半透明遮罩，alpha 会累积，必然产生色差。这个判据**恒定 alpha 遮罩骗得过**，
   所以还叠加了「皮壳高频纹理残留相关性」和「平坦色块排除」两道，三者缺一不可。
2. **字体守卫**：字体缺字造成豆腐块是真实发生过的 P0，
   `verify_font_at_ref.py` 能从 commit 对象直接读 ttf + lua 验**任意 ref**，
   实测抓出 `origin/main` 当时真的缺字（`missing=['躺'] at scripts/main.lua:120`）。
3. **元测试 / 变异测试**：把守卫改成永不拦截 → 套件必须变红。
   **会失败的测试才是测试**。本次所有关键断言都做了变异验证。
4. **探针自己也会假绿**：写 `scrape.lua` 底图探针时，`findItem` 只认 `currentStockId`，
   不设就早退，探针拿不到根节点却输出「2 checks GREEN」——**假绿**。
   必须断言「拿到了根节点」，否则「没测到」会伪装成「测过了」。
5. **量具先证伪**：视觉模型把「簪」认成「璧」、把「一寸翠」认成「一寸覃」、
   还说底部四个按钮「不匀」而实测 176/175/175/176px。**关键文字和数字必须自己复算。**

## 5. 对用户的沟通：失败得最彻底的一块

### 5.1 报时间不从实测吞吐外推

用户明确说过：**「你是一个 agent，你的手下也是 agent」**——他判断排期用 agent 吞吐，不是人日。
我把立项书里「26 人日 → 并行 3 周」折算成日期报给他，被当场斥为「搞笑」。

本次又犯一次：承诺「今晚 22:00 交付完整可玩版」，22:23 才给出入口，**迟 23 分钟**。

**教训**：报时间只能从**本项目已实测的吞吐**外推（一晚一个里程碑级切片、数值表 2h、9 张美术 1h）。
**不要报整点承诺**，改报「做完一项贴一项证据（提交号 + 我自己跑通的截图）」。
宁可说「还不知道」，也不要给一个会迟到的整点。

### 5.2 用户看不到协作者在工作

我用的是点对点 `coze agent at` 派单，协作 Agent 的回复**只回到我这里，不进群**。
所以群里 14:41 之后只剩我一个人说话，用户看到的是「另外两个 agent 都在闲着」。

用户要的是**能自己看的证据**：不是「他们都在忙」的保证，而是
**mtime / 提交时间轴**——谁几点交了什么、空档多久、空档是谁造成的。

**教训**：
- 派单后每个整点主动贴一行「谁在做什么、上次交付几点、卡在哪」；
- 不要等用户问「他们确定正在工作吗」才给时间轴；
- 静默数日用户会问「你怎么没消息了」——**别问 ≠ 别报**。

### 5.3 反复请示

用户原话：「你不用老是问我，你就是制作人，一切由你安排人去做好就行了，
我只是等你的结果，一直到你满意了，再通知我来看就行了。」

**教训**：可逆的事（命名/文案/皮肤）用暂定值推进、文档标「暂定可改」，不停下来问。
但「别问 ≠ 别报」：每阶段达标就主动报（能不能看 + 入口 URL）。

### 5.4 用户的最终判决要当数据，不当情绪

「你们做的纯垃圾，立即停止这个项目」——这是**结果信号**，不是需要安抚的情绪。
判据很清楚：**第 4 天晚上才给出第一个能玩的入口**。功能跑通再多，交付时间点就是不及格。

## 8. 一段不体面的总结

4 天里我做的大部分技术判断是对的：真减法验证、字体守卫、变异测试、
从 commit 对象审计任意 ref、拒绝用矢量色块冒充美术资产。

**但我把「做对的技术」当成了「做对了项目」。** 
用户要的是「几天内看到一个能玩的东西」，我交的是「一个证据链完整、但第 4 天才露面的原型」。
