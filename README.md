## 开工检查清单（摘自《一寸翠》§6，20 条）

### 开工前（不写一行代码）
1. 平台 + **该平台上的具体标的游戏**都拿到，两句缺一不动工。
2. 说「复刻」的，先取到**原作实机运行画面**（至少 8 屏各一帧），拿不到就改口径。
3. `get_ad_config` + 读 `.project/project.json`，确认 `project_id` / `app_id` / `developer_id` 与广告 `status`。
4. 所有「等平台 / 等 owner」的条目**当场实测一遍**，实测不通才记为阻塞，并写清谁办、入口在哪。
5. 出《立项说明书》+ 调研报告，本地起外网服务给用户审，**通过后才写代码**。

### 排期
6. 只从**本项目已实测吞吐**外推，不用人日折算。
7. **不报整点承诺**，报里程碑 + 每完成一项贴证据。
8. 验证基建预算 ≤ 总工时 20%。
9. 第一个可玩版本的时间点，不超过总周期的 **1/3**。

### 派单
10. 派前先查仓库有没有等价物，**跑一遍并量耗时**。
11. ≤15 分钟的活自己做，不派。
12. 每单一个唯一编号，回复必须引用编号；单回合 ≤10 分钟能收口，要并行就多派几个回合。
13. 协作 Agent 报的数字，换口径自己复算一遍。

### 优先级
14. 每轮先找「用户一眼看出的最大差异」，先补那个，再谈 1px。
15. 结构性缺失（背景垫、广告、存档）优先于细节打磨，哪怕细节可逆。
16. 三屏并排先 5 秒直觉判，再像素判。

### 交付
17. 「构建成功」≠「能跑」，必须自己按用户流程走一遍并截图。
18. 关键断言必须做变异验证（改坏实现 → 断言必须变红）；探针必须断言「真的拿到了被测对象」，防假绿。
19. 视觉识别的文字/数字必须自己复算（簪→璧、翠→覃 都误读过）。

### 沟通
20. 每整点主动贴「谁在做什么 / 上次交付几点 / 卡在哪」；用户问「能看了吗」时，只答「能，入口是 <URL>」或「还不能，因为 X」；给入口前自己走一遍用户流程并截图。
